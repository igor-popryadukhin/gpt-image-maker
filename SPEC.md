# Техническое задание

**Проект:** CLI утилита `gpt-image-maker`
**Язык реализации:** Python
**Назначение:** пакетная генерация изображений через OpenAI GPT Image API на основе текстового файла с описаниями и ссылками на исходные изображения.

---

## 1. Цель и задачи

Цель — автоматизировать массовую генерацию изображений (рендер автомобилей / объектов) на основе:

* текстовых данных из файла (бренд, модель, поколение, тип кузова и т.п.);
* исходного изображения, загружаемого по URL;
* шаблонного промпта, формируемого динамически.

Результат — PNG-изображения с прозрачным фоном, сохранённые в файловой структуре, строго соответствующей исходным URL.

---

## 2. Общий сценарий работы

1. Пользователь запускает CLI утилиту `gpt-image-maker` с параметрами (файл входных данных, шаблон промпта, параметры генерации и т.д.).
2. Утилита построчно читает входной текстовый файл.
3. Для каждой строки:

   * парсит данные (бренд, модель, период выпуска, поколение, тип кузова, URL исходного изображения);
   * скачивает исходное изображение по URL во временный каталог `tmp` рядом с входным файлом;
   * формирует промпт по шаблону, подставляя данные строки;
   * вызывает OpenAI GPT Image API (модель `gpt-image-1-mini`) с:

     * переданным исходным изображением;
     * сгенерированным промптом;
     * параметрами: размер, качество, формат, прозрачный фон и т.п.;
   * сохраняет сгенерированный PNG по целевому пути, полученному из URL (см. ниже).
4. В случае ошибок скачивания или генерации выполняются повторы (до N раз).
5. Ведётся прогресс, логирование, сохранение состояния выполнения для последующего возобновления.
6. При потере интернета выполнение приостанавливается, затем автоматически продолжается после восстановления связи.

---

## 3. Формат входных данных

### 3.1. Базовый формат строки

Каждая строка файла — CSV-строка вида:

```text
"avia", "d-series", "06.2006 -  н.в.", "1 поколение, рестайлинг", "Шасси", https://s.auto.drom.ru/i24262/c/photos/fullsize/avia/d-series/avia_d-series_1034587.jpg
```

Ожидаемые поля по умолчанию:

1. `brand` — марка (`"avia"`)
2. `model` — модель (`"d-series"`)
3. `production_period` — период выпуска (`"06.2006 -  н.в."`)
4. `generation` — поколение и рестайлинг (`"1 поколение, рестайлинг"`)
5. `body_type` — тип кузова (`"Шасси"`, `"Цельнометаллический фургон"` и т.п.)
6. `image_url` — абсолютный URL исходного изображения

### 3.2. Требования к парсеру

* Поддержка:

  * кавычек `"..."`;
  * разделителя по умолчанию `,` (запятая + возможные пробелы).
* Валидация:

  * обязательность поля `image_url`;
  * URL должен начинаться с `http://` или `https://`.
* Возможность задать:

  * пользовательский разделитель (`--delimiter`),
  * пользовательскую схему полей (`--columns`), при расширении формата (опционально, можно запланировать как будущий функционал).

При ошибке парсинга строка помечается как «ошибка разбора», записывается в лог и в файл ошибок.

---

## 4. Формирование промпта

### 4.1. Базовый пример

Пример целевого промпта (с учётом данных из строки):

> `"{brand} {model} {production_period}, {body_type}, {generation} в боковом варианте (в профиле) на белом фоне. Фон строго прозрачный. Автомобиль должен быть белого цвета."`

Пример с конкретикой:

> `Nissan Murano 2016, джип/suv 5 дв., 3 поколение, Z52 (08.2016 - 10.2022) в боковом варианта (в профиле) на белом фоне. Фон строго прозрачный. Автомобиль должен быть белого цвета.`

### 4.2. Шаблон промпта

* Шаблон задаётся:

  * либо через аргумент CLI `--prompt-template '...'`;
  * либо через файл `--prompt-template-file path/to/template.txt`.
* Внутри шаблона используются плейсхолдеры формата Python `str.format`:

  * `{brand}`, `{model}`, `{production_period}`, `{generation}`, `{body_type}`, `{image_url}`, а также любые дополнительные, если будут добавлены.
* При отсутствии нужного поля строка помечается как ошибка (ошибка данных).

## 5. Обработка изображений

### 5.1. Загрузка исходного изображения

* Загружать изображение по `image_url` с повторами:

  * количество попыток — по умолчанию 3, переопределяется `--download-retries`.
  * задержка между попытками — экспоненциальный backoff с максимумом (например, до 60 секунд).
* Файл сохраняется во временный каталог:

  * по умолчанию: `<директория_входного_файла>/tmp/`.
  * имя файла:

    * либо имя из URL (последний сегмент),
    * либо UUID с расширением, сохранённым из URL (если хочется избежать коллизий).
* При окончательной неудаче:

  * запись ошибки в лог;
  * фиксация ошибки в state;
  * переход к следующей строке.

### 5.2. Генерация выходного пути

Целевой путь сохранения PNG:

* Из `image_url` берётся часть пути после домена, без ведущего `/`, например:

  * URL:
    `https://s.auto.drom.ru/i24276/c/photos/fullsize/baic/ev5/baic_ev5_1105092.jpg`
  * Целевой путь:
    `i24276/c/photos/fullsize/baic/ev5/baic_ev5_1105092.png`

* Корень выходного каталога задаётся параметром `--output-root` (по умолчанию — тот же каталог, где находится входной файл).

* Если промежуточные директории не существуют — создаются автоматически.

* Если файл уже существует:

  * по умолчанию: пропуск (пометить как «уже обработано»);
  * опция `--overwrite` — перезаписывать.

## 6. Взаимодействие с OpenAI API

### 6.1. Модель и основные параметры

* Модель: `gpt-image-1-mini`
* Режим: генерация изображения на основе:

  * исходного изображения (из временного файла);
  * текстового промпта.

Настройки по умолчанию (должны быть переопределяемы CLI-опциями):

* **Размер**: `1536x1024` (Landscape)
* **Качество**: `high`
* **Формат**: `png`
* **Прозрачный фон**: включен
* **Partial images**: `none` (не используется частичное редактирование)

### 6.2. Конфигурация доступа

* API-ключ OpenAI:

  * берётся из переменной окружения `OPENAI_API_KEY`;
  * опционально — из конфигурационного файла (`--config config.yaml`), но не из аргумента CLI (чтобы не светить в history).
* Поддержка настройки базового URL (`--api-base-url`), на случай прокси/перенаправлений.

### 6.3. Обработка ошибок API

* Классы ошибок:

  * сетевые ошибки (нет интернета, таймауты);
  * ошибки авторизации/лимиты;
  * ошибки формата запроса.
* Повтор генерации:

  * до N попыток (по умолчанию 5, настраивается `--generation-retries`);
  * backoff задержка.
* Если после N попыток генерация не удалась:

  * запись ошибки в лог и файл ошибок;
  * переход к следующей строке.

## 7. Функциональные требования (детализация)

### 7.1. Сохранение состояния после сбоя

Требование: утилита должна уметь продолжать работу с места остановки (по файлу и строкам).

Реализация:

* State-файл, по умолчанию: `.gpt-image-maker.state.json` рядом с входным файлом (путь можно задавать `--state-file`).
* В state хранятся:

  * путь к входному файлу;
  * hash входного файла (например, SHA-256, для обнаружения изменений);
  * позиция (номер строки / смещение в файле);
  * статус обработки каждой строки (успех / ошибка / пропуск / в процессе);
  * метаданные последнего запуска (время, параметры).
* Поведение:

  * При запуске с тем же входным файлом утилита:

    * проверяет наличие state-файла;
    * если hash файла совпадает — предлагает (или по флагу `--resume` молча) продолжить с последней незавершённой строки;
    * если hash отличается — предупреждает и может начать заново (сброс state по флагу `--reset-state`).
  * Обновление state происходит атомарно (запись через временный файл и rename).

### 7.2. Прогресс выполнения

* В консоль выводится прогресс:

  * формат: `Processed X/Y (NN.N%) [OK: A, ERR: B, SKIP: C]`
  * при большом количестве строк — использовать прогресс-бар (например, `tqdm`).
* Опция `--no-progress` для отключения прогресса (в логах останется).

### 7.3. Логирование и сохранение ошибок

* Лог-файл (по умолчанию `gpt-image-maker.log` в директории входного файла, переопределяется `--log-file`).
* Уровни логирования: INFO / WARNING / ERROR / DEBUG (`--log-level`).
* Отдельный файл ошибок, например `gpt-image-maker.errors.csv`, с колонками:

  * номер строки;
  * исходная строка;
  * тип ошибки;
  * текст ошибки;
  * timestamp.

### 7.4. Пауза при пропаже интернета

* При сетевой ошибке (нет DNS, нет маршрута, таймауты):

  * утилита переходит в режим «ожидания сети»;
  * периодически выполняется проверка соединения:

    * либо через тестовый запрос к OpenAI API,
    * либо через ping/HTTP HEAD к настраиваемому URL (`--ping-url`).
  * до восстановления сети:

    * не читаются новые строки;
    * прогресс не продвигается;
    * пользователю выводится статус «Ожидание сети...». 
* После успешной проверки:

  * обработка продолжается с текущей строки;
  * в лог пишется событие восстановления связи.

### 7.5. Показ окна «до/после»

Требование: «Показывать окно изображение до и после».

* Реализовать опциональный режим предпросмотра:

  * флаг `--preview` включает показ визуального окна после успешной генерации.
* Поведение:

  * после генерации изображения:

    * утилита открывает окно (например, на `tkinter` или через библиотеку `Pillow + simple GUI`);
    * отображает слева исходное изображение, справа — сгенерированное;
  * пока окно открыто:

    * в простом варианте выполнение блокируется до закрытия окна пользователем;
    * либо реализовать таймер автозакрытия по `--preview-timeout` (в секундах).
* Для чисто серверного режима (без GUI) по умолчанию предпросмотр выключен.

## 8. CLI интерфейс

### 8.1. Основная команда

```bash
gpt-image-maker run \
    --input-file path/to/data.txt \
    --output-root /path/to/output/root \
    --prompt-template-file prompt.txt \
    --download-retries 3 \
    --generation-retries 5 \
    --size 1536x1024 \
    --quality high \
    --format png \
    --transparent-background \
    --state-file .gpt-image-maker.state.json \
    --log-file gpt-image-maker.log \
    --preview
```

### 8.2. Основные опции

Обязательные:

* `--input-file` — путь к входному файлу.
* `--output-root` — корневая директория для сохранения PNG (если не задана — директория входного файла).

Параметры промпта:

* `--prompt-template` — строковый шаблон промпта.
* `--prompt-template-file` — файл с шаблоном промпта (приоритет выше).
* `--locale` (опционально) — язык/локаль промпта, если нужен.

Параметры генерации:

* `--size` — размер, например `1536x1024`.
* `--quality` — `high` / `standard` (если API поддерживает).
* `--format` — `png` (по умолчанию).
* `--transparent-background` / `--no-transparent-background`.
* `--model` — имя модели (`gpt-image-1-mini` по умолчанию).

Параметры обработки:

* `--download-retries N` — количество попыток скачивания исходного изображения (default 3).
* `--generation-retries N` — количество попыток генерации (default 5).
* `--concurrency N` (опционально, если потребуется) — количество параллельных задач (с учётом лимитов API).
* `--resume` — продолжить с сохранённого state без вопросов.
* `--reset-state` — игнорировать существующий state и начать заново.

Логирование и вывод:

* `--log-file path`
* `--log-level {DEBUG,INFO,WARNING,ERROR}`
* `--no-progress` — отключить прогресс-бар.
* `--preview` — включить показ окна «до/после».
* `--preview-timeout N` — автозакрытие окна предпросмотра через N секунд (0 — не закрывать автоматически).

Сеть и API:

* `--api-base-url` — базовый URL для OpenAI.
* `--ping-url` — URL для проверки сети.
* `--timeout` — общий таймаут запросов (секунды).

## 9. Нефункциональные требования

* **Платформы:** Linux, macOS, Windows.
* **Версия Python:** не ниже 3.10.
* **Зависимости:**

  * официальный Python-клиент OpenAI;
  * библиотека для HTTP (requests / httpx);
  * библиотека для CLI (`argparse`, `click` или `typer`);
  * по необходимости — `tqdm` для прогресса;
  * `Pillow` и `tkinter` (или эквивалент) для предпросмотра.
* **Кодировка:** UTF-8.
* **Производительность:**

  * обработка больших файлов (десятки тысяч строк);
  * аккуратная работа с лимитами API (возможность задать `--rate-limit` в будущем).

## 11. Тестирование

* Юнит-тесты:

  * парсинг строк входного файла;
  * построение промпта (шаблоны / плейсхолдеры);
  * вычисление выходного пути по URL;
  * сохранение/чтение state-файла.
* Интеграционные тесты:

  * мок OpenAI API (без реальных запросов);
  * сценарий: нормальный проход по нескольким строкам;
  * сценарий с имитацией падения сети и последующим возобновлением.
* Ручные тесты:

  * предпросмотр до/после;
  * большие файлы (тысячи строк).

## 12. Безопасность

* API-ключ:

  * не хранить в логах;
  * не принимать через CLI аргумент (чтобы не оставлять в history).
* Обработка ошибок:

  * не выводить в лог чувствительные данные запросов/ответов.
